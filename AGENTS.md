# Agent Instructions — Timely3

Форк TimelyNG (цепочка: `cynorg/PebbleTimely` → `eldios/TimelyNG` → `vvzvlad/Timely3`).
Вотчфейс для Pebble: C99 под Cortex-M3 + PebbleKit JS для страницы настроек.

## Структура

- `src/` — код вотчфейса. `Timely.c` — монолит (~2300 строк): жизненный цикл,
  все обработчики AppMessage, создание/уничтожение слоёв, тики, перевёрстка.
- `src/js/` — телефонная часть: `app.js` (погода, приём настроек),
  `configpage.js` (генерация страницы), `config.js` (спека полей),
  `wirekeys.js` (позиционный wire-контракт, только APPEND).
- `tests/` — хостовые юнит-тесты (`utest.h`) для чистых модулей.
- `tools/` — гейты: `test.sh` (общий), `strict-check.sh` (флаги облака),
  `reloc-check.sh` (выравнивание релокаций).
- `AUDIT.md` — текущий разбор багов с фиксами. Читать перед правками.
- `STORE.md` — почему публикация в стор ручная и как её делать.

## Setup

```bash
nix develop                 # pebble CLI + ARM toolchain + эмулятор
pebble sdk install latest   # первый раз, кэшируется в ~/.pebble-sdk
```

## Тесты и сборка

```bash
just test                       # хостовые юнит-тесты
nix develop -c sh tools/test.sh # полный гейт: тесты + сборка + reloc + strict
just run                        # собрать и поставить в эмулятор
```

## Соглашения

- **Комментарии в коде — на английском.** Отчёты и обсуждение — на русском.
- **Байт-гранулярность persist-структур.** `persist` и `persist_adv_settings`
  пишутся во flash целиком, поэтому их байтовая раскладка — контракт
  совместимости с блобом, который уже лежит на часах после прошлой сборки;
  `_Static_assert` в `settings.h` нужны, чтобы её изменение было заметным на
  компиляции, а не тихим. Ловят они не всё: вставку, удаление и смену ширины
  поля — да, а размер-нейтральную правку (перестановка полей одинаковой ширины
  или подмена поля на такое же по ширине) проходят молча — кроме случая, когда
  она задевает поле, названное в офсетном `_Static_assert` (`track_battery`,
  `theme_mode`, `weather_icons`): такую сборка уронит. В остальных местах структур
  от неё страхуют офсеты, прибитые в `tests/test_settings_layout.c`, и то лишь
  для перечисленных там полей; остальные поля — на ревью глазами. Поля только `uint8_t`/`int8_t`/`char[]`,
  **никогда** указатель: адресный инициализатор в packed-структуре даёт
  невыровненную `R_ARM_ABS32`, и загрузчик отвергает приложение целиком.
  Новые поля — только в конец. Сознательное изменение раскладки `persist`
  (вставка, удаление, перестановка поля) допустимо, но обязано идти вместе
  с бампом `PERSIST_SETTINGS_VERSION` в `settings.h`: `init()` в `Timely.c`
  сверяет версию прочитанного блоба и при несовпадении выбрасывает его целиком,
  откатываясь на дефолты из `settings.c`, — иначе устаревший блоб будет не
  отвергнут, а прочитан не теми полями. У `persist_adv_settings` версии нет,
  для него допустима только дозапись в конец.
- **Три слоя должны сходиться** при добавлении настройки: `package.json`
  (`messageKeys`), `AK_*` + обработчик в `Timely.c`, `config.js`/`wirekeys.js`.
  Порядок в `wirekeys.js` — wire-формат, переставлять и удалять нельзя.
- **Секреты — только из ENV/secrets**, ни одного значения в коде или workflow.
- Тесты для нового кода пишутся сразу; в CI `build` зависит от `test`.
- Повторяющиеся действия — через `just`/`make`, не разрозненными командами.
