# Публикация в стор

## Почему это не автоматизировано

У Rebble developer portal **нет публичного API для загрузки приложений**. Вся
официальная документация — [Publishing an App](https://developer.rebble.io/guides/appstore-publishing/publishing-an-app/),
[Preparing a Submission](https://developer.rebble.io/guides/appstore-publishing/preparing-a-submission/),
[Submit an app](https://help.rebble.io/appstore-submission/) — описывает только
ручную загрузку `.pbw` через веб-форму: «Add a release» → выбрать файл → «Save» →
после перезагрузки страницы «Publish» рядом с релизом. Программного эндпоинта,
токена или CLI-команды для этого не существует.

Второе ограничение — со стороны самого стора: релиз принимается, только если его
версия **строго больше** всех ранее опубликованных, а UUID не занят. То есть
«публиковать при каждом пуше» невозможно и по механике портала — второй пуш с той
же версией был бы отвергнут, а бампать версию на каждый коммит бессмысленно.

## Что делает CI вместо этого

- **Любой пуш в любую ветку** → прогон тестов, сборка `.pbw` под все четыре
  платформы, проверка выравнивания релокаций, загрузка артефакта. Артефакт
  скачивается со страницы run'а.
- **Пуш тега `v*`** → GitHub Release с приложенным `.pbw` и автогенерированными
  заметками.

То есть бинарник всегда собирается сам и всегда доступен готовым к загрузке;
ручным остаётся только последний шаг — сама загрузка в портал.

## Ручной шаг (2 минуты)

1. Поднять версию в `package.json` (и в остальных местах — см. `AUDIT.md`, L15:
   версия продублирована руками в пяти файлах).
2. Обновить `CHANGELOG.md` — его содержимое и есть текст для поля «Release notes».
3. Поставить тег: `git tag v0.0.8 && git push origin v0.0.8`.
4. Дождаться Release, скачать `.pbw`.
5. На [dev-portal.rebble.io](https://dev-portal.rebble.io/): «Add a release» →
   загрузить `.pbw` → вставить заметки → «Save» → перезагрузить страницу →
   «Publish».

## Если API однажды появится

Точка расширения — джоб `release` в `.github/workflows/build-release.yml`.
Токен портала класть **только** в `secrets` репозитория и читать из `env:`;
никаких значений в коде или в workflow-файле.
